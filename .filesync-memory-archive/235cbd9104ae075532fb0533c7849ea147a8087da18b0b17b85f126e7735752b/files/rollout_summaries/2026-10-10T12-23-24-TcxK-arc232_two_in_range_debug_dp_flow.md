## Task 2: 从朴素 DP 推导严格线性解法

Outcome: success

Preference signals:

- 用户先要求“教我正解怎么做吧”，并反复要求“一步一步、展开说、引入变量时说清楚定义”，还说“不要一句带过” -> 教学应一次推进一个核心步骤，但每一步完整解释符号、时刻、条件、转移和例子，避免跳跃。
- 用户在困惑时要求先看 `n^3 DP` 再逐步优化，而不是直接给最终代码 -> 应先建立可验证的朴素状态，再说明压缩依据。

Key steps:

- 以最近三个 `1` 的位置刻画区间：若处理到 `r`，记 `p1>p2>p3`，则 `[l,r]` 恰有两个 `1` 当且仅当 `p3<l≤p2`。
- 预处理：`a[i]` 为所有 `R≤i` 的区间左端点最大值，`b[i]` 为所有 `R≥i` 的区间左端点最小值。通过前缀 `max`、后缀 `min` 得到单调数组；扫描到 `i` 时要求 `p2≥a[i]`、`p3<b[i]`。
- 朴素 DP：`f_i[u][v]` 表示前 `i` 位合法且倒数第二、最后一个 `1` 在 `u,v`。填 `0` 时 `(u,v)→(u,v)`，需 `u≥a[i]`；填 `1` 时 `(u,v)→(v,i)`，需 `v≥a[i]` 且 `u<b[i]`。复杂度 `O(n^3+m)`、空间 `O(n^2)`。
- 压缩：固定最后一个 `1` 的位置形成一列。用 `p[k]` 表示第 `k` 列的实际位置，用 `L[k],R[k]` 表示该列建立时可行的倒数第二个位置编号区间，即状态 `(p[j],p[k])` 对所有 `L[k]≤j≤R[k]`。
- 处理位置 `i` 时，`[x,y]` 表示满足 `a[i-1]≤p[j]<b[i]` 的旧倒数第二位置编号；旧列 `k` 可转移当且仅当 `p[k]≥a[i]`、`R[k]≥x`、`L[k]≤y`。由于 `p,L,R` 单调，合法旧列是连续区间，可用四个全局单调指针维护。
- 已实现线性代码 `work/interval_sum_two_linear_explained.cpp`，编译通过。验证：4094 组 C++ 暴力小数据通过；总 `N=500000` 边界批次通过；逐层比较压缩状态与完整 DP 的 6094 组测试通过。

Reusable knowledge:

- `L[k],R[k]` 存的是列建立时“真实可行 DP 状态”的候选编号范围，不是任意位置范围；`p[k]` 是该列固定的最后一个 `1`。新增 `1` 后，旧状态的 `v` 变成新状态的 `u`，因此旧列编号范围会成为新列的 `L,R`。
- 四指针均只右移：`x,y` 维护旧 `u` 的允许窗口，`l,r` 维护可转移旧列的编号范围；总时间 `O(n+m)`，空间 `O(n)`。

References:

- 线性实现：`work/interval_sum_two_linear_explained.cpp`
- 状态结构验证：`work/check_interval_sum_two_state_structure.py`
- 官方搜索确认题目为 AtCoder ARC232 A “Two in the Range”；官方编辑说明了 `dp[z]` 为可作为前驱的位置集合，集合连续且左右端点单调，可用双指针做到 `O(N+M)`。

- 对每个未固定为 `0` 的位置，找出包含它的连续区间编号 `[u,v]`，在顶点 `u..v+1` 间加容量 `1` 的边 `u→v+1`。选择该边等价于令该位置为 `1`；每个原区间对应一条割，区间和为 2 等价于从 1 到 `k+1` 存在值为 2 的流，判断最大流是否至少 2。官方说明复杂度 `O(N+M)`。

Reusable knowledge:

- 网络流建模的核心是：剩余区间按端点排序；每个位置对应覆盖它的连续区间段 `[u,v]`，加边 `u→v+1` 容量 1；一条从源到汇的单位流选择一个位置，穿过的区间恰好是包含该位置的区间。两条边互不共享容量意味着每个区间恰好被两个选中位置覆盖。
