# 分治跨中点子序列统计的预处理复杂度与状态转移

Rollout context: 用户质疑一个声称为 \(O(nk^2\log n)\) 的分治做法中，如何在线性扫描端点时提前准备左右区间信息。

## Task 1: 解释分治区间的线性（按位置）预处理

Outcome: uncertain

Preference signals:

- 用户直接追问“这个怎么线性提前准备好”，说明其关注的不只是复杂度结论，还要求明确说明如何避免对每个端点重复做 DP。类似问题应给出可维护状态、单次加入的更新范围和总复杂度证明。

Key steps:

- 对固定分治节点 \([s,t]\)，取中点 \(m\)，左侧从 \(m\) 向左扫描，右侧从 \(m+1\) 向右扫描；每个位置只加入一次。
- 左侧维护 \(B_{p,v}\)：当前区间内，最小值至少为 \(p\)、最大值恰好为 \(v\) 的非空不下降子序列数。向左加入 \(x\) 时，新增序列必须选 \(x\)，其最大值为 \(v\ge x\)，新增量为 \(w_v=B^{old}_{x,v}+[v=x]\)，并对所有 \(p\le x\) 更新 \(B_{p,v}\mathrel{+}=w_v\)。
- 扫描到左端点 \(L\) 后保存 \(b_{L,v}=B_{1,v}\)。一次加入更新最多 \(O(k^2)\) 个矩形位置。
- 右侧对称维护 \(C_{u,p}\)：最小值恰好为 \(u\)、最大值至多为 \(p\) 的非空不下降子序列数。向右加入 \(x\) 时，先取 \(w_u=C^{old}_{u,x}+[u=x]\)（\(u\le x\)），再对所有 \(p\ge x\) 更新 \(C_{u,p}\mathrel{+}=w_u\)。扫描到右端点 \(R\) 后保存 \(c_{R,u}=C_{u,k}\)，并在线性 \(O(k)\) 时间内求其后缀和。
- 因此一个分治层的所有区间准备总计 \(O(nk^2)\)，递归深度为 \(O(\log n)\)，整体为 \(O(nk^2\log n)\)。跨中点询问随后用左右摘要及后缀和直接计算。

Failures and how to do differently:

- “线性提前准备”容易被误解为每次加入仅 \(O(1)\)；实际是对位置数线性、对值状态为 \(O(k^2)\)。应明确区分单个端点的更新成本与整个分治层的成本。
- 该轮没有用户对最终解释的明确确认或代码/测试验证，因此只能标记为 uncertain。

Reusable knowledge:

- 通过维护带有最小值/最大值边界的二维计数状态，可以在扫描中点两侧时增量构造所有端点摘要，避免每个 \(L,R\) 独立运行子序列 DP。

References:

- 用户问题： “回到那个 n k^2 log n 的做法，这个怎么线性提前准备好”

- 右侧更新：\(w_u=C^{old}_{u,x}+[u=x]\)，\(C_{u,p}\mathrel{+}=w_u\)（\(u\le x,p\ge x\)）。
