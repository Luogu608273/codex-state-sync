# Minecraft 携带版历史版本与 Java 玩法对应考证

Rollout context: 用户通过回忆 iOS 携带版中的蘑菇房、藤蔓、附魔、展示框、铁砧、平滑光照、侦测器和黏液块装置，试图确定实际对应的版本及 Java 版玩法阶段。用户特别纠正：要按“对应的玩法/特征版本”比较，而不是按同期发布日期直接对应。

## Task 1: 根据游戏特征定位携带版版本并映射 Java 版本

Outcome: partial

Preference signals:

- 用户明确纠正“不是同期版本，而是对应的版本”，说明类似历史版本问题应优先按实际功能集合和玩法阶段建立对应关系，不能简单按发布日期一一换算。
- 用户连续补充关键特征（“有铁砧”“有侦测器和粘性活塞，活塞推动粘液块可以把村民弹起”），说明应在新证据出现后重新收窄版本，而不是坚持早先的粗略判断。
- 用户纠正“不是突然变黑……平滑光照是失效的，就是每格亮度完全相同”，说明需要准确复述视觉现象，区分整体变暗、光照等级跳变和平滑光照/环境光遮蔽失效。

Key steps:

- 检索确认携带版 0.9.0 加入无限世界、巨型蘑菇、藤蔓和接近 Java 1.7.2 的生物群系；仅凭蘑菇房无法区分 0.9 与 0.10。
- 确认携带版 0.12.1 已有附魔台和铁砧，而物品展示框到 0.14.0 才加入；若铁砧与展示框属于同一段记忆，最早应是 0.14.0。
- 确认 0.14.0 已有黏液块、漏斗、比较器、投掷器、发射器和展示框，但没有活塞、黏性活塞或侦测器，因此只能粗略对应 Java 1.7～1.8，偏向 Java 1.8 的玩法特征。
- 用户补充侦测器、黏性活塞和黏液块弹射村民后，定位到携带版至少 0.15.0；该版本于 2016 年 6 月发布，并加入活塞、黏性活塞和侦测器。
- Java 对照中，Java 1.8 已支持黏液块连接活塞并弹射实体；侦测器则是更晚加入，因此若要求“侦测器也存在”，不能把整组功能直接等同于 Java 1.8，回答中给出 Java 1.11 作为同时满足条件的粗略单版本参照。

Failures and how to do differently:

- 早期回答把用户记忆的“平滑光照失效”误解为封顶后房间变暗；后续才根据用户澄清改为“每个方块面内亮度均匀、相邻方块之间跳变”。未来应先确认现象含义，再用它做版本判断。
- “携带版 0.14.0 对应 Java 1.8”只能作为功能阶段的近似，不是严格版本等价；应明确列出已匹配和未匹配的特征，尤其是红石组件跨版本错位。
- 侦测器的 Java 版本映射需要谨慎：Java 1.8 可解释黏液块弹射，但侦测器并非 Java 1.8 特征。若用户要求精确对应，应分别说明“功能首次出现版本”和“整体玩法最接近版本”，不要只给一个版本号。

Reusable knowledge:

- 携带版 0.9.0：无限世界、巨型蘑菇、藤蔓以及接近 Java 1.7.2 的主世界生物群系；0.9.0 记录还提到更新光照和平滑光照只对部分方块增加/移除。
- 携带版 0.12.1：附魔台、铁砧；携带版 0.14.0：物品展示框、黏液块及大量红石组件；携带版 0.15.0：活塞、黏性活塞、侦测器。
- 若同一段记忆明确包含物品展示框、铁砧、附魔物品，则时间下限是 0.14.0；若还包含侦测器和黏性活塞，则时间下限提升至 0.15.0。
- “活塞推动黏液块使村民弹起”本身可由 Java 1.8 的黏液块-活塞机制解释，但“同时存在侦测器”需要更晚的 Java 版本；携带版功能组合不能简单映射到同一个 Java 发布版本。
