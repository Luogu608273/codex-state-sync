# 网易云音乐排序核查与明日方舟肉鸽种子入口查询

Rollout context: 用户先要求整理二游歌曲热度榜，随后纠正“热度值相同也有平台排序”的问题，最后询问明日方舟肉鸽如何使用种子开局。

## Task 1: 网易云二游歌曲排序规则

Outcome: partial

Preference signals:
- 用户明确纠正：“不对不对，你研究一下网易云相同热度是怎么排的”——类似榜单任务不能把公开字段中的相同热度值直接视为并列或自行用评论数替代，必须核查网易云实际返回顺序及其排序语义。
- 用户接受将评论数作为备选指标，但随后再次要求回到网易云相同热度的实际排序，说明其更重视平台原生排序而非代理指标。

Key steps:
- 调用网易云接口核对塞壬唱片-MSR（artist id 32540734）的热门歌曲和 `/api/v1/artist/songs?id=32540734&order=hot`。
- 发现多首歌曲 `popularity=100`，但接口仍返回稳定顺序；前六首顺序与截图一致。
- 进一步验证该顺序不是评论数排序：如《铁花飞》约8083条评论，却排在约25285条评论的《Speed of Light》之前。
- 查到 API 封装中 `artist_songs` 的 `order=hot` 只是请求网易云后端热门排序，未披露可解释的具体 tie-break 算法。

Failures and how to do differently:
- 初始把所有歌曲的 `popularity=100` 当作无法排序，随后错误改用评论数；用户指出截图显示存在明确顺序。以后应优先保留官方/接口返回顺序，并明确“热度字段相同，平台内部排序规则未公开”，不要伪造严格数值排名。

Reusable knowledge:
- `/api/artist/{artist_id}` 或 `/api/artist/top/song?id={artist_id}` 返回歌手热门作品顺序；`/api/v1/artist/songs?id={artist_id}&order=hot` 可复核热门排序，`order=time` 则按时间。
- `popularity`/`score` 均可能被压缩为100，不能单独用于细排；评论总数也不是网易云热门作品排序依据。
