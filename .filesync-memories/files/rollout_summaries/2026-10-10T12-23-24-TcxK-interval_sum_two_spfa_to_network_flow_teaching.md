## Task 1: 保留截断 SPFA 的启发式优化

Outcome: partial

Preference signals:

Key steps:

- 修正差分约束建图：前缀和节点 `1..n+1`；每个 `[l,r]` 加 `l -> r+1 (2)`、`r+1 -> l (-2)`；相邻点加 `i -> i+1 (1)`、`i+1 -> i (0)`。
- 发现原 SPFA 出队后没有清除 `vis[u]`，导致节点被跳过；多测还需要清理 `vis/tot/head`。
- 按用户要求保留“操作次数超限即判 No”的 heuristic，改为连续边存储、数组栈/SLF 队列、全点初始化，并在三种顺序 `{2,0,1}` 间复用当前距离。
- 工作文件：`work/interval_sum_two_fast.cpp`。
- 本地验证：编译成功；通过 2094 组小数据（`n<=5` 穷举 + 1000 随机）、28 组最大规模已知有解数据、25 万组多测检查。构造出原程序约 1.78 秒误判 `No` 而新版约 0.22 秒输出 `Yes` 的有解数据。

Failures and how to do differently:

- 原程序把操作次数超限当作负环，会将有解数据误判为 `No`；这是启发式截断而非正确判定。
- 未获得官方提交/AC 结果；当前代码仍可能因三轮超限输出错误 `No`。
- 普通未截断 SPFA 最坏仍为 `O(n(n+m))`；当前所谓时间上界只来自人为截断，不能宣称算法正确或严格线性。

Reusable knowledge:

- 截断版本固定 `B=5e6`，三轮合计常数较大，空间 `O(n+m)`；普通 SPFA 负环判断不能保证 `O(n+m)`。
- 一次成功松弛的计数不能重复累加；曾出现 `sum` 对同一次松弛加两次的 bug。

## Task 2: 正解推导与网络流方向

Outcome: partial

Preference signals:

- 用户后来明确“我打算放弃这个做法了。教我正解怎么做吧”，并反复要求“一步一步、每个变量定义清楚、不要一句带过”；未来教学应一次推进一个关键步骤，但把符号、时间点、转移原因和例子讲完整。
- 用户在理解困难后说“你说话能不能展开说……不要一句带过”，并要求从 `n^3 DP` 开始逐步讲到完成 -> 需要先建立朴素 DP，再压缩，避免直接跳到单调指针。
- 用户明确切换为“你教我网络流做法吧”，但本轮只完成了检索和确认，尚未实际讲解网络流；不要把网络流方案当作用户已掌握。

Key steps:

- 已推导朴素 DP：处理前 `i` 位，`f_i[u][v]` 表示倒数第二个和最后一个 `1` 的位置；放 `0` 保持 `(u,v)`，放 `1` 转为 `(v,i)`。朴素复杂度 `O(n^3)`、空间 `O(n^2)`。
- 已验证线性压缩 DP：将同一最后一个 `1` 的状态按列保存，列内候选编号为连续区间；用 `p[k]、L[k]、R[k]` 和四个单调指针实现 `O(n+m)`。代码 `work/interval_sum_two_linear_explained.cpp` 编译成功，并通过 4094 组暴力数据、总规模边界测试，以及 6094 组逐层状态集合一致性检查。
- 检索到本题 ARC232 A 官方网络流另一解法：先删除被其他区间包含的区间，并将包含关系导致的外围位置固定为 `0`；剩余区间按左、右端点递增编号。对每个未固定为 `0` 的位置 `p`，找其包含的连续区间编号 `[u,v]`，建立容量为 `1` 的边 `u -> v+1`。选该边等价于令 `x_p=1`；每个原区间对应一个割，跨过该割的边正好是包含该区间的位置。因此所有区间和恰为 `2` 当且仅当图中存在值为 `2` 的流，答案等价于最大流至少为 `2`。官方说明该方案 `O(N+M)`。

Failures and how to do differently:

- 教学过程中曾在用户尚未理解“列”和 `L/R` 时过早引入压缩结构，造成多次澄清；未来应先用具体状态例子解释“列固定的是旧状态的 `v`，列内区间记录的是旧状态的 `u`”，再讲区间交和指针。
- 网络流方案尚未给出完整、从区间包含删除到建图、最大流判定的推导或代码；下一次应从用户明确要求的网络流方案开始，不继续默认讲 DP 压缩。

Reusable knowledge:

- 恰好两个 `1` 的局部判定：扫描到 `r`，最近三个 `1` 的位置为 `p1>p2>p3`（缺失记 `0`），则 `[l,r]` 恰有两个 `1` 当且仅当 `p3<l<=p2`。
- 官方网络流建模的核心是“位置选 `1` = 选一条跨越其所包含区间连续段的容量 1 边；每个区间和 = 对应割容量”。

References:

- 本地验证输出：`C++ PASS 4094 brute-force cases`；`PASS 6094 cases: every prefix state checked; exhaustive brute force for n <= 5`
