# P12445 数好图：先等待用户思路，后解释容斥 DP

Rollout context: 用户希望在对话中学习洛谷 P12445，最初明确要求“先不用给提示，等我说我的做法”。随后用户改变请求，要求先检查题目中可能陌生的技巧并告知；之后追问“把容斥写进 DP”是否类似 P2151 的减法。

## Task 1: 题面确认与等待用户思路

Outcome: success

Preference signals:

- 用户明确说“先不用给提示，等我说我的做法” -> 讲题时应先确认题面和约束，不主动泄露解法或关键观察，等待用户提交思路。

Key steps:

- 读取项目 `.agents/skills/oi-training/SKILL.md`，确认提示规则：先确认约束和用户推导；若无明确卡点，只给一个推动问题或观察，不追加完整解法。
- 核实题面：给定 N 和素数 P，统计仅含 `i→j (i<j)` 的简单 DAG，使恰有 K 个点同时满足从 1 可达且可达 N；`2≤N≤2000`。
- 回复“题面看过了，等你说你的做法”，没有提前给出算法。

Reusable knowledge:

- 该项目的信息学训练流程要求区分提示、复盘和独立重做；用户未给出思路时不要直接讲完整解法。

References:

- 题目：洛谷 `P12445 [COTS 2025] 数好图 / Promet`
- 技能文件：`.agents/skills/oi-training/SKILL.md`

## Task 2: 检查可能陌生的技巧并解释“容斥写进 DP”

Outcome: success

Preference signals:

- 用户后来主动要求“先帮我检查一下这道题有什么科技或者技巧我可能不会的，然后告诉我” -> 在用户明确改变请求后，可以先做技巧诊断，但应只指出值得确认的技巧，避免直接泄露完整推导。
- 用户用 P2151 类比追问容斥含义 -> 解释新技巧时应联系用户熟悉的旧题，但明确指出两者差异。

Key steps:

- 查阅洛谷题解和训练档案。题解显示核心是将点按可达性分类，并使用容斥与 `O(N^2)` 计数 DP；训练档案中没有明确记录用户掌握“把容斥写进 DP”。
- 告知用户：本题没有明显需要先补的重型科技，主要值得确认的是“把容斥写进 DP”；另一个潜在卡点是分类计数后判断哪些边选择能独立相乘。
- 用户提到 P2151。核对后说明：P2151 中“所有转移减去唯一回头边”是单个坏条件的容斥；本题涉及多个坏条件，需要处理交集。
- 用两坏条件 `A,B` 说明：总数减去 `|A|`、`|B|`，再加回 `|A∩B|`。写进 DP 时，对每个坏条件分成“不钦定”和“钦定发生”两支，钦定分支符号取反；不钦定分支并不禁止该坏条件发生，最终通过符号抵消实现容斥。

Failures and how to do differently:

- 本轮没有验证用户对该解释的理解，也没有进入 P12445 的具体状态设计；后续应等待用户继续提出自己的理解或做法，再按项目规则指出一个具体断点/问题，不要一次展开完整题解。

Reusable knowledge:

- 训练档案显示用户常见卡点包括“把方案拆开计数后判断能否独立相乘”，且历史题目多为提示后完成、未独立重做；不要仅凭讨论或 AC 推断已稳定掌握。
- P12445 的公开题解一致指向：利用 DAG 的可达性分类、容斥计数和二维 DP，整体目标复杂度为 `O(N^2)`；这些是后续讲解方向，但本轮尚未向用户展开完整算法。
